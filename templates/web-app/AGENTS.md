# Clay web app

Internal prototype generated by Clay Studio. Clay 1.0 is the standard this app follows: one stack, an approved plan, and the definition of done in `docs/code.md`.

## Commands

- `npm install`
- `npm run dev` — Vite client + Express on localhost
- `npm start` — Express serves API and built client
- `npm test`

## Hard rules

- JavaScript + JSDoc. Zod at every HTTP boundary. Change the contract before the handler.
- Nouns in URLs, verbs in methods. `/v1/requests`, never `/createRequest`.
- Every write sends `Idempotency-Key`. A missing key is 400. A retry returns the first result.
- Errors are `{ code, message, requestId }`. `code` comes from `server/contracts.js` and is never renamed.
- Status changes go through `transitionRequest`. An illegal jump is rejected.
- Pure functions. Do not mutate shared data. Compare with `===`. Screens stay under 50 lines and use Clay tokens.
- No customer, payment, HR, or secrets in prompts, logs, or seed data.
- Fix open npm security issues before the change is done. Upgrade a direct dependency when the patched release is newer. Do not downgrade a package to clear an advisory.
- `/plan` before implementation. Claude writes the plan. A person approves it. Grok 4.7 High codes. Update the docs in the same change as the behavior.
- Agents open pull requests. A person merges.

## Where to look
